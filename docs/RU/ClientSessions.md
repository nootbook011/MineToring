# Клиентские сессии в Minecraft Bedrock

**Сессии** — это связка данных, позволяющая игроку (или боту) авторизоваться на сервере повторно, сохраняя прогресс, местоположение и инвентарь.

> **Пример:** Бот выходит из игры и заходит заново точно так же, как обычный игрок — он появляется на том же месте со всеми вещами в инвентаре.

---

## Состав данных сессии

Данные делятся на критически важные для идентификации и вспомогательные.

### Обязательные данные
*Эти поля являются решающими для привязки данных к конкретному игроку.*

* `uuid` — уникальный идентификатор клиента на сервере.
* `selfSignedId` — уникальная цифровая подпись клиента.

### Необязательные данные
*Могут использоваться античитами или прокси-серверами для проверки «подлинности» устройства.*

* `pfid` — добавлен в новых версиях. Не влияет на игровые данные: игрок успешно авторизуется, даже если это поле изменено или отсутствует.
* `deviceId` — ID устройства. Аналогично `pfid`, несет второстепенную роль.

---

## Жизненный цикл и применение

### Где передаются данные?
Процесс авторизации проходит внутри **Login Packet**, там передаются все основные идентификаторы (`uuid`, `selfSignedId` и др.).

### Практическое использование
В рамках класса **CustomPClient** библиотеки **MineToring** сессии применяются для локального хранения данных бота. Это позволяет запоминать состояние клиента и восстанавливать его при перезагрузке без создания нового игрового профиля на сервере.
