# Class: BedrockDimension наследует [BedrockPlugins](./BedrockPlugins.md)

Класс представляет собой контейнер для данных конкретного игрового измерения (Overworld, Nether, End). Он управляет сеткой загруженных чанков (`BedrockMap`), списком сущностей и игроков (`BedrockEntities`), и предоставляет API для добавления, получения и валидации игровых данных.

## Свойства

### `chunks`
**Тип**: `BedrockMap`

Возвращает экземпляр `BedrockMap`, содержащий все загруженные чанки в этом измерении. Позволяет прямой доступ к чанкам по координатам.

### `length`
**Тип**: `number`

Возвращает общее количество загруженных чанков в измерении.

### `entities`
**Тип**: `BedrockEntities`

Возвращает экземпляр `BedrockEntities`, управляющий всеми сущностями в измерении (мобы, предметы, боевые огни и т.д.).

### `players`
**Тип**: `{ name: BedrockPlayer }`

Удобный геттер для доступа к списку активных игроков в данном измерении. Эквивалентно `dimension.entities.players`.

### `events`
**Тип**: `EventEmitter`

Экземпляр `EventEmitter` для прослушивания событий, происходящих внутри измерения (добавление сущностей, обновления и т.д.).

---

## События

Измерение генерирует следующие события (эмитируются через `EventEmitter`):

| Событие | Параметры | Описание |
| :--- | :--- | :--- |
| `newEntity` | `entity: BedrockEntity` | Вызывается при добавлении новой сущности (моба) |
| `newPlayer` | `player: BedrockPlayer` | Вызывается при добавлении нового игрока |

## Методы добавления данных

Класс автоматически парсит пакеты протокола Bedrock и обновляет внутреннее состояние.

### `add(packets)`
Универсальный метод для добавления данных о мире за один вызов.

**Параметры**:
- `packets` (`Object`): Объект с пакетами
  - `chunk` (`Object`): Пакет `level_chunk` (опционально)
  - `subChunks` (`Object`): Пакет `subchunk` (опционально)

### `addEntity(entityPacket, typeEntity = 0)`
Добавляет сущность в измерение и автоматически парсит её данные.

**Параметры**:
- `entityPacket` (`Object`): Пакет с данными сущности
- `typeEntity` (`number`): Тип сущности
  - `0` — Обычная сущность (мобы)
  - `1` — Игрок
  - `2` — Предмет

**Возвращает**: `BedrockEntity | BedrockPlayer`

### `addChunk(levelChunkPacket)`
Парсит и добавляет полный чанк в карту измерения.

**Параметры**:
- `levelChunkPacket` (`Object`): Пакет `level_chunk` от сервера

**Возвращает**: `BedrockChunk` (только что добавленный чанк)

**Примечание**: Чанк должен быть добавлен перед добавлением его подчанков.

### `addSubChunks(subChunkPacket)`
Добавляет данные подчанков в измерение.

**Параметры**:
- `subChunkPacket` (`Object`): Пакет `subchunk` от сервера

**Требования**: Основной чанк (`addChunk`) должен быть загружен перед добавлением подчанков.

## Методы получения данных

### `getChunk(x, z)`
Возвращает объект чанка по его координатам без парсинга или модификации.

**Параметры**:
- `x` (`number`): Координата X чанка
- `z` (`number`): Координата Z чанка

**Возвращает**: `BedrockChunk | undefined` (undefined если чанк не загружен)

### `getEntity(runtimeId)`
Поиск сущности по её уникальному `runtimeId`.

**Параметры**:
- `runtimeId` (`number`): Уникальный идентификатор сущности

**Возвращает**: `BedrockEntity | undefined`

## Методы работы с чанками

### `async validateChunk(x, z)`
Выполняет полную валидацию и декодирование чанка с использованием адаптера данных (например, PrismarineAdapter).

**Параметры**:
- `x` (`number`): Координата X чанка
- `z` (`number`): Координата Z чанка

**Возвращает**: `Promise<BedrockChunk | false>`

**Процесс**:
1. Получает чанк из карты
2. Если чанк существует, декодирует его через адаптер
3. Возвращает декодированный чанк или `false`

**Требования**:
- Чанк должен быть предварительно загружен через `addChunk()`
- `ValidateAdapter` должен быть загружен в плагины

### `_clear()`
Полностью очищает карту чанков и список сущностей.

**Использование**:
- При смене измерения
- При переподключении к серверу
- При сбросе состояния

## Плагины-зависимости

Для корректной работы необходимо передать уже инициализированный класс `ProtocolValidator`:

* **ProtocolValidator** (Обязательно): Содержит парсеры и базу данных протокола
* **ValidateAdapter** (Опционально): Адаптер для декодирования чанков (обычно `PrismarineAdapter`)
* **BlobsManager** (Опционально): Менеджер кэширования чанков
