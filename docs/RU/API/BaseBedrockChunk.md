## Свойства

### `position`
**Тип**: `V2{ x, z }`

Координаты чанка на карте.  
Важно: Это не мировые координаты, а координаты чанка в сетке чанков мира.

* **set**: Если входные данные являются валидным объектом `V2{ x, z }`, устанавливает координаты, в противном случае пропускает запись.

### `dimension`
**Тип**: `number`

Измерение, в котором находится чанк.

### `from`
**Тип**: `V3{ x, y, z }`

Мировые координаты нижнего угла чанка.

### `to`
**Тип**: `V3{ x, y, z }`

Мировые координаты верхнего угла чанка.

### `hasSubChunks`
**Тип**: `Boolean`

Возвращает `true`, если в чанке зарегистрирован хотя бы один подчанк.

### `hasBiomes`
**Тип**: `Boolean`

Возвращает `true`, если в чанке зарегистрирован хотя бы один биом.

### `subChunks`
**Тип**: `Object<number, BedrockSubChunks>`

Возвращает объект со всеми подчанками, где ключом является координата `y`.

### `biomes`
**Тип**: `Object<number, PalettedStorage | ProxyPalettedStorage>`

Возвращает объект со всеми картами биомов в каждой секции чанка, где ключом является координата `y`.

## Методы

### `create(x, z, dimension)`
Заполняет чанк базовыми данными. Перед вызовом обязательно нужно инициализировать зависимости методом `.init` или передать их в конструкторе, иначе выбросит исключение.

**Параметры**:
- `x` (`number`): Координата X чанка в мировой сетке чанков.
- `z` (`number`): Координата Z чанка в мировой сетке чанков.
- `dimension` (`number`): `dimensionId` измерения, в котором находится целевой чанк.

**Выбрасывает**: 
- `TypeError`: Если зависимости не определены методом `.init`.

### `buildFromPacket(chunkPacket, BlobsManager? = undefined)`
Создаёт чанк из сетевого пакета `level_chunk`, заполняет класс данными, парсит полезную нагрузку и автоматически добавляет чанк в карту хешей, если передан `BlobsManager`.

**Параметры**:
- `chunkPacket` (`Object`): Сетевой пакет `level_chunk`.
- `BlobsManager` (`BlobsManager|undefined`): Карта хешей.

### `setPayload(payload, cache?)`
Автоматически декодирует буфер данных из сетевого пакета `level_chunk` и заполняет собственный класс данными.

**Параметры**:
- `payload` (`Array|Buffer`): Полезная нагрузка чанка.
- `cache` (`boolean`): Получена ли полезная нагрузка в режиме кэширования данных сервером. Это необходимо, так как данные и порядок декодирования отличаются при включённом и выключенном кэшировании. Если параметр не передан, а класс был создан с помощью готового пакета, метод автоматически возьмёт данные о кэшировании из этого пакета чанка.

**Возвращает**: `boolean`

### `setBorderBlocksPayload(payload)`
Автоматически декодирует буфер данных из сетевого пакета `level_chunk`, отвечающий за расположение барьеров в чанке, и заполняет родительский класс данными о них.

**Параметры**:
- `payload` (`Array|Buffer`): Полезная нагрузка чанка.

**Возвращает**: `boolean`

### `getSubChunk(y, autoCreate? = true)`
Возвращает конкретный подчанк по его вертикальному индексу. Если подчанк отсутствует, создаёт новый пустой подчанк и возвращает его.

**Параметры**:
- `y` (`number`): Y-индекс подчанка в чанке.
- `autoCreate` (`boolean`): Если значение `true`, то при запросе несуществующего подчанка будет создан новый. В противном случае метод вернёт `undefined`.

**Возвращает**: [`BedrockSubChunk`](./BaseBedrockSubChunk.md)|`undefined`

### `createSubChunk(y)`
Создаёт новый подчанк на основе данных родительского чанка и добавляет его в структуру чанка, только если координата Y входит в границы подчанков для данного измерения. В противном случае возвращает `false`.

**Параметры**:
- `y` (`number`): Y-индекс подчанка в чанке.

**Возвращает**: [`BedrockSubChunk`](./BaseBedrockSubChunk.md)|`false`

### `setSubChunk(y, subChunk)`
Регистрирует уже существующий класс подчанка в структуре чанка.

**Параметры**:
- `y` (`number`): Y-индекс подчанка в чанке.
- `subChunk` ([`BedrockSubChunk`](./BaseBedrockSubChunk.md)): Класс подчанка.

### `getBorder(x, z)`
Возвращает `true`, если по локальным координатам в чанке установлено ограничение барьером (например, созданное блоком барьера `border_block`).

**Параметры**:
- `x` (`number`): Координата X.
- `z` (`number`): Координата Z.

**Возвращает**: `boolean`

### `setBorder(x, z, boolean)`
Изменяет значение барьера по координатам в чанке.

**Параметры**:
- `x` (`number`): Координата X.
- `z` (`number`): Координата Z.
- `boolean` (`boolean`): Новое значение координаты.

### `getBiome(x, y, z)`
Возвращает данные биома по конкретным координатам в чанке.

**Параметры**:
- `x` (`number`): Координата X.
- `y` (`number`): Координата Y.
- `z` (`number`): Координата Z.

**Возвращает**: `MinecraftData.Biome` — Данные целевого биома из `minecraft-data`.


### `getBiomeId(x, y, z)`
Возвращает ID биома по локальным координатам в чанке.

**Параметры**:
- `x` (`number`): Локальная координата X блока в чанке.
- `y` (`number`): Локальная координата Y блока в чанке.
- `z` (`number`): Локальная координата Z блока в чанке.

**Возвращает**: `number`

### `setBiomeId(x, y, z, id)`
Устанавливает ID биома по локальным координатам в чанке.

**Параметры**:
- `x` (`number`): Локальная координата X блока в чанке.
- `y` (`number`): Локальная координата Y блока в чанке.
- `z` (`number`): Локальная координата Z блока в чанке.
- `id` (`number`): Целевой ID биома.

**Возвращает**: `number`

### `getBlock(x, y, z)`
Возвращает полные данные конкретного блока в чанке.

**Параметры**:
- `x` (`number`): Локальная координата X блока в чанке.
- `y` (`number`): Локальная координата Y блока в чанке.
- `z` (`number`): Локальная координата Z блока в чанке.

**Возвращает**: [`BedrockBlock`](./BaseBedrockBlock.md)

### `setBlock(block, x, y, z)`
Устанавливает данные из класса [`BedrockBlock`](./BaseBedrockBlock.md) по указанным локальным координатам в чанке.

> [!WARNING]
> Метод изменяет данные только в локальном хранилище и не передаёт изменения на сервер!

**Параметры**:
- `block` (`BedrockBlock`): Целевой класс блока.
- `x` (`number`): Локальная координата X блока в чанке.
- `y` (`number`): Локальная координата Y блока в чанке.
- `z` (`number`): Локальная координата Z блока в чанке.

**Возвращает**: `boolean`

### `getBlockId(x, y, z, l)`
Возвращает `runtimeId` блока на конкретном слое чанка.

**Параметры**:
- `x` (`number`): Локальная координата X блока в чанке.
- `y` (`number`): Локальная координата Y блока в чанке.
- `z` (`number`): Локальная координата Z блока в чанке.
- `l` (`number`): Слой целевого блока.

**Возвращает**: `number`

### `setBlockId(x, y, z, l, id)`
Устанавливает `runtimeId` блока на конкретном слое чанка.

> [!WARNING]
> Метод изменяет данные только в локальном хранилище и не передаёт изменения на сервер!

**Параметры**:
- `x` (`number`): Локальная координата X блока в чанке.
- `y` (`number`): Локальная координата Y блока в чанке.
- `z` (`number`): Локальная координата Z блока в чанке.
- `l` (`number`): Слой целевого блока. 
- `id` (`number`): Новый `runtimeId` блока.
