# Class: BedrockSubChunk наследует [BedrockObjectStorage](./BedrockObjectStorage.md)

Класс для управления данными подчанка (секции чанка). Он является частью структуры родительского класса чанка и предоставляет доступ к данным конкретного вертикального слоя блоков.

## Свойства

### `position`
**Тип**: `V3{ x, y, z }`

Координаты подчанка на карте чанков мира и внутри родительского чанка.  
Важно: Это не мировые координаты, а координаты подчанка в сетке чанков мира.

* **set**: Если входные данные являются валидным объектом `V3{ x, y, z }`, устанавливает данные координат, в противном случае пропускает запись.

### `dimension`
**Тип**: `number`

Измерение, в котором находится чанк.

### `from`
**Тип**: `V3{ x, y, z }`

Мировые координаты нижнего угла чанка.

### `to`
**Тип**: `V3{ x, y, z }`

Мировые координаты верхнего угла чанка.

### `hasBlocks`
**Тип**: `boolean`

Возвращает `true`, если в чанке зарегистрирован хотя бы один блок.

### `blocks`
**Тип**: `Array<PalettedStorage>`

Возвращает массив слоёв, каждый из которых содержит хранилище всех блоков в нём. Обычно подчанк имеет всего два слоя:
- **0**: Основной слой блоков.
- **1**: Содержит только блоки, которые могут находиться внутри других блоков (например, вода или снег, находящиеся внутри забора или листвы).

## Методы

### `create(x, z, dimension)`
Заполняет подчанк базовыми данными. Перед вызовом обязательно нужно инициализировать зависимости методом `.init` или передать их в конструкторе, иначе выбросит исключение.

**Параметры**:
- `x` (`number`): Координата X чанка в мировой сетке чанков.
- `z` (`number`): Координата Z чанка в мировой сетке чанков.
- `dimension` (`number`): `dimensionId` измерения, в котором находится целевой чанк.

**Выбрасывает**: 
- `TypeError`: Если зависимости не определены методом `.init`.

### `setPayload(payload, cache?)`
Автоматически декодирует буфер данных из пакета `subChunk` и заполняет собственный класс данными.

**Параметры**:
- `payload` (`Array|Buffer`): Полезная нагрузка подчанка из пакета `subChunk`.
- `cache` (`boolean`): Получена ли полезная нагрузка в режиме кэширования данных сервером. Это необходимо, так как данные и порядок декодирования отличаются при включённом и выключенном кэшировании. Если параметр не передан, а родительский класс чанка был создан с помощью готового пакета, метод автоматически возьмёт данные о кэшировании основываясь на данных этого пакета.

### `setBlocksEntityPayload(payload)`
Автоматически декодирует буфер данных из пакета `subChunk`, отвечающий за данные сущностей блоков в подчанке, и заполняет ими собственный класс.

**Параметры**:
- `payload` (`Array|Buffer`): Полезная нагрузка подчанка из пакета `subChunk`.

### `getLayer(layer)`
Возвращает класс хранилища данных для конкретного слоя блоков.

**Параметры**:
- `layer` (`number`): Слой данных.

**Возвращает**: `PalettedStorage`

### `setLayer(layer, storage)`
Устанавливает класс хранилища данных для конкретного слоя блоков.

**Параметры**:
- `layer` (`Number`): Слой данных.
- `storage` (`PalettedStorage`): Класс хранилища данных.

### `getBlock(x, y, z)`
Возвращает полные данные конкретного блока в подчанке.

**Параметры**:
- `x` (`number`): Локальная координата X блока в подчанке.
- `y` (`number`): Локальная координата Y блока в подчанке.
- `z` (`number`): Локальная координата Z блока в подчанке.

**Возвращает**: [`BedrockBlock`](./BaseBedrockBlock.md)

### `setBlock(block, x, y, z)`
Устанавливает данные из класса [`BedrockBlock`](./BaseBedrockBlock.md) по указанным локальным координатам в подчанке.

> [!WARNING]
> Метод изменяет данные только в локальном хранилище и не передаёт изменения на сервер!

**Параметры**:
- `block` (`BedrockBlock`): Целевой класс блока.
- `x` (`number`): Локальная координата X блока в подчанке.
- `y` (`number`): Локальная координата Y блока в подчанке.
- `z` (`number`): Локальная координата Z блока в подчанке.

**Возвращает**: `boolean`

### `getBlockEntity(x, y, z)`
Возвращает данные `EntityNbt` для конкретного блока в подчанке.

**Параметры**:
- `x` (`number`): Локальная координата X блока в подчанке.
- `y` (`number`): Локальная координата Y блока в подчанке.
- `z` (`number`): Локальная координата Z блока в подчанке.

**Возвращает**: `Object`

### `setBlockEntity(x, y, z, data)`
Устанавливает данные `EntityNbt` для конкретного блока в подчанке.

**Параметры**:
- `x` (`number`): Локальная координата X блока в подчанке.
- `y` (`number`): Локальная координата Y блока в подчанке.
- `z` (`number`): Локальная координата Z блока в подчанке.
- `data` (`Object`): Данные `EntityNbt` для блока.

### `getBlockId(x, y, z, l)`
Возвращает `runtimeId` блока на конкретном слое подчанка.

**Параметры**:
- `x` (`number`): Локальная координата X блока в подчанке.
- `y` (`number`): Локальная координата Y блока в подчанке.
- `z` (`number`): Локальная координата Z блока в подчанке.
- `l` (`number`): Слой целевого блока.

**Возвращает**: `number`

### `setBlockId(x, y, z, l, id)`
Устанавливает `runtimeId` блока на конкретном слое подчанка.

**Параметры**:
- `x` (`number`): Локальная координата X блока в подчанке.
- `y` (`number`): Локальная координата Y блока в подчанке.
- `z` (`number`): Локальная координата Z блока в подчанке.
- `l` (`number`): Слой целевого блока. 
- `id` (`number`): Новый `runtimeId` блока.
